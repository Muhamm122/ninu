# Instagram Brand Management

## Overview

Manage an Instagram brand account end-to-end: plan content, write captions, design posting schedule, manage DMs/funnel, and track performance. Designed for product-based brands (furniture, fashion, food, etc.) selling to Indonesian audience with WhatsApp conversion funnel.

## Workflow

```
1. Brand Audit → understand current account, niche, audience
2. Style Guide → colors, photo style, voice, grid pattern
3. Content Calendar → 30-day plan with themes, types, posting times
4. Caption Library → templates by category (education, product, lifestyle, testimonial, promo)
5. Hashtag Strategy → primary + secondary + niche + location tags
6. DM/WA Funnel → auto-reply templates, FAQ, lead tracking
7. Automation → cron posting, DM reply, analytics
```

## Content Calendar Structure

### Weekly Theme Pattern
Each week has a theme that ties posts together:
- Week 1: Brand awareness (intro, best sellers, story)
- Week 2: Education (tips, material guide, how-to)
- Week 3: Aspirational lifestyle (room tours, mood boards)
- Week 4: Trust + conversion (testimonials, flash sale)

### Daily Post Types
| Time (WIB) | Type | Why |
|------------|------|-----|
| 08:00 | Story | Morning scroll |
| 12:00 | Reel/Photo | Lunch break |
| 17:00 | Story | After-work |
| 19:00 | Carousel/Photo | **Peak engagement** |
| 21:00 | Story | Night scroll, soft sell |

### Content Mix Ratio
- Education/Tips: 25% → build authority
- Product Showcase: 25% → drive desire
- Lifestyle/Aspirational: 20% → build brand
- Testimonials/Social Proof: 15% → build trust
- Behind the Scenes: 10% → build connection
- Promo/Selling: 5% → convert (soft)

## Caption Formula

```
[HOOK — 1 line that stops the scroll]

[ELABORATION — 3-5 lines deepening the story]

[PRODUCT DETAIL / BENEFIT — what and why]

[CTA — DM / WA / Link]

[HASHTAGS — 20-33 tags]
```

### Hook Types (rotate across posts)
- **Provocative:** "90% orang salah pilih sofa"
- **Aspirational:** "Kamar tidur yang bikin ogah bangun"
- **Question:** "Tau ga sih, material ini tahan 20 tahun?"
- **Story:** "Ibu Rina uda 3 bulan pake dan bilang..."
- **Data:** "Floating rack = ruangan nampak 2x luas"
- **FOMO:** "3 unit tersisa untuk harga ini"

## Hashtag Strategy

### Structure per post (20-33 total)
1. **Brand tags** (2-3): `#brandName` + `#brandTagline`
2. **Niche primary** (5-7): core product category tags
3. **Niche secondary** (10-15): rotate per post, broader category
4. **Long-tail product** (3-5): specific product tags
5. **Location** (2-3): city/region tags
6. **Community** (2-3): small engaged communities

### Rule
Never reuse exact same hashtag set 2 posts in a row — rotate secondary and long-tail tags.

## DM / WhatsApp Funnel

```
IG POST/STORY (awareness)
    → DM CONVERSATION (interest + consideration)
        → WHATSAPP (conversion — catalog, quote, order)
            → PAYMENT (Midtrans / Transfer / COD)
                → DELIVERY UPDATE (photo before ship)
                    → POST-DELIVERY (testimoni request → UGC)
                        → RETENTION (promo, new collection, referral)
```

### DM Auto-Reply Categories
1. **Harga inquiry** — ask product + budget + location, redirect to WA
2. **Katalog request** — send WA link with catalog
3. **Custom order** — ask dimensions + finish + reference photo
4. **Ongkir/delivery** — compute shipping cost
5. **Follow-up** — warm lead nudge after 1-2 days

### Lead Status Tracking
NEW → WARM → HOT → QUOTE SENT → NEGOTIATING → ORDERED → DELIVERED → LOST

## Style Guide Essentials

### Photography (Indonesian product brands)
- ✅ Natural light, golden hour preferred
- ✅ Context shots (product in styled room) > isolated product
- ✅ Consistent warm-toned editing
- ✅ Detail shots (texture, stitching, joints)
- ❌ No flash, no red carpet backdrop, no heavy watermarks

### Feed Grid Pattern
Alternate between product/lifestyle/education — never 3+ product shots in a row or the feed becomes a catalog.

## Execution Style

When user says "jalankan satu persatu" or "one by one", **do NOT attempt all deliverables simultaneously**. Execute sequentially:
1. Present the full list of deliverables first
2. Complete #1 fully before starting #2
3. Mark each completed in a todo list
4. If a step is blocked (e.g., no GPU for image gen), skip it, explain briefly, and proceed to next — do NOT stall

## Image Generation Constraints

AI-generated product mockups require either:
- **ComfyUI local** — needs NVIDIA GPU ≥6GB VRAM (most cloud VMs don't have one)
- **Cloud API** — requires paid API key (Together AI, Replicate, Stability AI, Comfy Cloud paid tier)
- **Free APIs** — Pollinations.ai returned 402 (Payment Required) as of June 2026; most "free" image gen APIs have moved to paid models

**When server has no GPU and no paid API key is available:**
1. Tell the user AI mockups are blocked — be brief, don't repeat
2. Suggest alternatives: generate on their laptop, use real product photos, or provide an API key
3. Move on to next deliverable immediately — do NOT get stuck

**Real product photos > AI mockups** for furniture/interior brands anyway — customers trust authenticity.

## Blocked Task Protocol

When a deliverable is blocked (no GPU, no API key, IP flagged, etc.):
1. **State the blocker ONCE** — one sentence, maximum two
2. **Offer 1-2 concrete alternatives** the user can act on
3. **Move to the next deliverable** — skip the blocked one, mark it cancelled
4. **Never repeat the blocker** in subsequent messages — the user heard you the first time
5. **Never ask "Mau task lain?"** after a blocker — just proceed to the next item

This is critical for user trust. Repeating why something doesn't work feels like lecturing, not helping.

## Username Availability Checking

To check if an IG username is available without logging in, use the mobile API endpoint:

```bash
curl -s -H "User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36" \
  -H "X-IG-App-ID: 936619743392459" \
  "https://i.instagram.com/api/v1/users/web_profile_info/?username=TARGET" \
  -o response.json -w "%{http_code}"
```

**Result interpretation:**
- HTTP 200 + response contains `"id"` field → **TAKEN** (parse `edge_followed_by.count` for follower count)
- HTTP 200 + response has no `"id"` or `user: null` → **AVAILABLE**
- HTTP 404 → **AVAILABLE**
- HTTP 401 → **RATE LIMITED** — back off, rotate `X-IG-App-ID`, add 3-5s delay between checks

**Rate limit rules:**
- Max ~15 consecutive checks before 401 rate limit kicks in
- After rate limit, the block is **IP-level, persistent for hours**, not just minutes — rotating app IDs, user agents, and waiting 30-120s will NOT reset it (confirmed: still 401 after 3+ minute waits and ID rotation)
- **Batch all username checks in one pass** — you likely won't get a second batch before the IP is burned
- Add `sleep 3-5` between each request in batch mode
- Rotate `X-IG-App-ID` values: `936619743392459`, `735923892429730`, `124024574876181`
- **Do NOT waste time retrying after 401** — move on, mark unchecked names as ❓, and tell user to verify manually
- **Failed approaches** (do NOT retry): browser navigation to `instagram.com/username/` (login wall), picuki.com (Cloudflare 403), imginn.com (403), SocialBlade (403), DuckDuckGo (captcha), Google search (IP captcha on datacenter), `?__a=1&__d=dis` embed endpoint (0-byte 201), GraphQL query endpoint (400 — deprecated)
- For unchecked usernames: tell user to verify manually via IG Settings → Edit Profile → try changing username (zero risk, current name stays if new one is taken)

**Batch checking pattern:**
```bash
usernames=("name1" "name2" "name3")
for u in "${usernames[@]}"; do
  sleep 3
  curl -s -H "X-IG-App-ID: 936619743392459" \
    "https://i.instagram.com/api/v1/users/web_profile_info/?username=${u}" \
    -o /tmp/ig_check.json -w "%{http_code}"
  # Parse result...
done
```

**Do NOT attempt** to check via `instagram.com/username/` in browser — IG redirects all unauthenticated profile views to login wall from datacenter IPs. Also do NOT attempt third-party IG viewers (picuki, imginn, socialblade) — they all return 403 from datacenter IPs.

## Username Naming Strategy

When recommending new IG usernames for a brand, evaluate across these dimensions:

| Dimension | Weight | Questions |
|-----------|--------|-----------|
| **Aesthetic match** | 30% | Does the name match the visual brand? (dark/modern → "haus", "oak"; crafty → "craft", "made") |
| **Market language** | 25% | Indonesian market → Indonesian words rank higher (ruang, mebel, kayu, rumah) |
| **Search SEO** | 20% | Keywords people actually search in IG Explore (living, mebel, interior) |
| **Memorability** | 15% | Shorter is better, no dot is cleaner (nanahaus > nana.haus), one word is ideal |
| **Uniqueness** | 10% | Less likely to collide with existing accounts |

**Naming categories for furniture/home brands:**
- **Dark/Modern:** haus, dwell, oak, timber, darkwood
- **Minimal/Premium:** living, home, space, room, interior, furn
- **Indonesian market:** ruang, mebel, kayu, rumah, duduk
- **Craftsmanship:** woodwork, craft, made, wood
- **Cross-language premium (high appeal for Indonesian brands):** haus (German: house), dwelling, habitat — creates premium mystique while remaining understandable

**Key insight:** For Indonesian furniture brands targeting dark/modern aesthetic, **cross-language premium names** (e.g., "haus living") outperform generic Indonesian names ("mebel jati") in:
- Perceived quality (imports/European = premium)
- IG Explore reach ("living" is a high-volume keyword)
- Brand scalability (no personal name lock-in)
Trade-off: less immediate recognition by mass market, but the mystique IS the brand signal.

**Domain check:** Always verify `.com` and `.id` availability alongside IG username. Use DNS lookup:
```bash
curl -s "https://dns.google/resolve?name=DOMAIN&type=A"
```
If no `"Answer"` section → domain likely available.

**Process:** Generate 20-30 candidates across categories → batch check availability → rank available ones by the 5 dimensions above → present top 5 with reasoning.

## Instagram Access from Server

IG blocks access from datacenter IPs (AWS, GCP, etc.) — both login wall and bot detection on third-party viewers (imginn, pikdo). This is NOT fixable without a residential proxy. See `residential-proxy` skill for setup.

You do NOT need direct IG access to create content — all deliverables (calendar, captions, style guide, DM templates) can be produced without logging in.

**User preference (Adib):** User prefers "agent siapin konten, user post sendiri" over full automation. Do NOT suggest logging into IG or providing credentials. Content-prep-only workflow is the correct default. User leans toward premium/abstract brand names (chose "haus_living1" / "Haus Living" over descriptive names like "nana.mebel"). User prefers underscore when clean name is taken (haus_living1 > haus.living for reliability of tagging).

## Pitfalls

- ❌ Posting 3+ product shots in a row — kills engagement, looks like catalog
- ❌ Same hashtag set every post — IG shadowban risk
- ❌ Ignoring DMs for >2 hours — hot leads go cold fast
- ❌ Selling in every post — 95% value, 5% sell
- ❌ Using only English hashtags — Indonesian audience searches in Indonesian too
- ❌ Not tracking lead status — leads slip through cracks
- Over-editing product photos — customers feel deceived when real product differs
- ❌ White studio background for furniture — looks like catalog, not lifestyle
- ❌ Bright flash lighting — flattens wood texture, looks cheap
- ❌ Storing API tokens via code — Hermes auto-masks all secrets before file writes (becomes `***`, invalid token). User must paste tokens manually via SSH or edit systemd service `Environment=` line directly
- ❌ `allow_re_entry=True` in python-telegram-bot v20+ ConversationHandler — removed; use `per_user=True` instead
- ✅ Alternate content types in feed grid
- ✅ Rotate hashtags per post
- ✅ Reply DM within 1 hour
- ✅ Route all serious inquiries to WhatsApp for closing
- ✅ Request customer photos after delivery (UGC goldmine)
- ✅ Track which posts generate most DMs — double down on that format
- ✅ Dark/warm background for furniture photos — pops in feed
- ✅ Context shots over isolated product shots
- ✅ Offer bundles with 10-15% discount to increase AOV

## Automation (Cron Jobs)

Set up 4 cron jobs for ongoing IG management. The agent does NOT post to IG directly — it sends the user ready-to-use captions and reminders via their chat (Telegram/WhatsApp).

### Cron 1: Daily Post Reminder (08:00 daily)
Read the 30-caption-batch file + content calendar. Send today's caption + hashtag + posting time + photo tip. User just copy-pastes to IG.

### Cron 2: Evening Prep (21:00 daily)
Preview tomorrow's content — what to post, what photo to prepare, quick styling tip. User preps the night before so morning posting is frictionless.

### Cron 3: Weekly Review (Sunday 20:00)
Summarize the week: what was posted, what was missed, KPI snapshot, recommendation for next week. Tone: encouraging, not pressuring.

### Cron 4: Monthly Refresh (1st of month 10:00)
Generate fresh 30-day calendar + 30 captions for the new month. Rotate weekly themes, add seasonal events, cover products not yet featured. Save to new files (e.g., `content-calendar-next.md`, `30-caption-next.md`).

### Cron setup pattern (Hermes):
```
cronjob action=create name="[brand]-daily-post" schedule="0 8 * * *" prompt="[read files, output caption for today]" enabled_toolsets=["file"]
cronjob action=create name="[brand]-evening-prep" schedule="0 21 * * *" prompt="[read files, output prep for tomorrow]"
cronjob action=create name="[brand]-weekly-review" schedule="0 20 * * 0" prompt="[review week, recommendations]"
cronjob action=create name="[brand]-monthly-refresh" schedule="0 10 1 * *" prompt="[generate new month content]"
```

## Rebrand Workflow

When a brand changes its IG username/name, update ALL assets systematically. **Do not skip steps** — stale references damage credibility.

### Step 1: User changes username in IG
User does this manually (Settings → Edit Profile → Username). Agent cannot do this safely. Suggest: try `hausliving` first (no dot/underscore = harder to mistype), fallback to `haus_living` or `haus.living`.

### Step 2: Rename project directory
```bash
mv ~/.hermes/[old-brand]/ ~/.hermes/[new-brand]/
```

### Step 3: Find-and-replace in ALL files
```bash
cd ~/.hermes/[new-brand]
find . -type f \( -name "*.md" -o -name "*.py" -o -name "*.html" -o -name "*.json" \) -exec sed -i \
  -e 's/@old.handle/@new.handle/g' \
  -e 's/old.handle/new.handle/g' \
  -e 's/Old Brand Name/New Brand Name/g' \
  -e 's/old-brand/new-brand/g' \
  {} +
```
Verify: `grep -r "old.brand\|Old Brand Name" . | wc -l` should return 0.

### Step 4: Update landing page
- Logo initials (e.g., NF → HL)
- Navbar brand name
- Title tag
- Footer copyright
- Any hardcoded @mentions in HTML

### Step 5: Update cron jobs
For each cron job: `cronjob action=update job_id=X name="[new-brand]-daily-post" prompt="[updated prompt with new brand name and file paths]"`

### Step 6: Create announcement content
Write rebrand post content: feed caption, story sequence, reel script, DM broadcast, WA broadcast. Save to `announcement-rebrand.md`.

### Step 7: Update memory
Replace old brand name in persistent memory.

### Key insight on naming: underscore vs dot
- `hausliving` (no separator) — hardest to mistype, cleanest, but less visual separation
- `haus_living` (underscore) — clear separation, still one word for tagging, slightly less premium-looking
- `haus.living` (dot) — most premium visual, BUT people forget the dot when typing → lost tags/mentions
- **Recommendation:** prioritize no-separator for brands, underscore as fallback when taken

## Logo & Watermark Generation

When the user needs a brand logo or watermark, generate **SVG files** programmatically (no GPU, no API key needed) then convert to PNG.

### Logo Generation Workflow

1. **Design SVG** — Write SVG with brand-appropriate colors, typography, and icon (house, sofa, monogram, etc.)
2. **Convert to PNG** — Use `rsvg-convert` (install: `sudo apt install librsvg2-bin`):
   ```bash
   rsvg-convert -w 1080 -h 1080 logo.svg > logo.png
   ```
3. **Generate multiple variations** — At minimum: (a) icon+text, (b) wordmark, (c) monogram. Present all to user.
4. **Save to** `~/.hermes/[brand]/logo/`

### Design Parameters (Furniture/Home brands — dark modern aesthetic)

| Element | Value |
|---------|-------|
| Background | `#1A1A1C` to `#2C2C2C` (charcoal gradient) |
| Accent | `#D4A574` (honey/oak) or `#C4735B` (terra) |
| Typography | Serif (Georgia/Playfair) for premium feel |
| Size | 1080×1080 (IG profile/post) |
| Font loading | No — use system fonts in SVG for portability |

### Watermark Types

| Type | Position | Opacity | Best For |
|------|----------|---------|----------|
| `catalog` | Bottom-right corner | 15% (very subtle) | Product catalog, website, PDF |
| `content` | Full-width bottom bar | 65% bg, 80% text | IG feed posts, carousel |
| `reel` | Top-left badge | 70% bg, 90% text | Reels, Stories, TikTok |

### Watermark Tool

Use the Python watermark script at `scripts/watermark.py`:
```bash
# Single image
python3 ~/.hermes/[brand]/watermark.py foto.jpg --type catalog

# Batch folder
python3 ~/.hermes/[brand]/watermark.py batch ~/foto-produk/ --type content --output ~/watermarked/
```

The script uses Pillow (PIL) — no GPU or API required. It renders "HL" monogram + brand name directly via Pillow ImageDraw at calibrated opacity and position per watermark type.

### Key insight
**SVG → PNG logo generation is zero-cost** (no GPU, no API). Combined with the Pillow-based watermark tool, the entire brand visual asset pipeline (logo + watermarks for all content types) runs on any server. This avoids the AI image generation blocker entirely for brand identity assets.
