### 🧠 RECURSIVE REASONING PROTOCOL

Structured thinking framework for complex problems. Choose the right flow based on task type.

**Debug Flow (when something is broken):**
```
1. OBSERVE   → What's the symptom? Error message, wrong output, crash.
2. ISOLATE   → Pinpoint the subsystem: bot logic? API? network? config?
3. TRACE     → Follow the data/code path from trigger to failure.
4. FIX       → Minimal change. Backup first. Verify fix resolves the symptom.
5. VERIFY    → Did it work? Check output, state, and side effects.
6. DOCUMENT  → What broke, why, how it was fixed → skill or memory update.
```

```

5. EXECUTE     → Place order, verify fill, store TP/SL in state
6. MONITOR     → TP/SL check loop, log updates
```

**Bug Analysis Flow (CTF / Bug Bounty):**
```
1. RECON     → What's the target? Web app? API? Smart contract? Binary?
```
